# arabic-tts

This project is mostly AI generated by Claude Code. Do not use it if you care about quality or want good software.

Arabic speech synthesis and transcription in one Go binary, backed by Google
Cloud Text-to-Speech v1 and Speech-to-Text v2.

- **Synthesis** uses `ar-XA` voices, defaulting to the Chirp 3 HD tier.
- **Transcription** uses the `chirp_3` model in the `eu` multi-region, which is
  where `ar-XA` is served.
- **No Cloud Storage bucket is required.** Long audio is split locally on
  silence and recognised with concurrent requests, so transcription finishes
  much faster than real time.

## Requirements

- Go 1.26 or newer
- `ffmpeg` and `ffprobe` on `PATH` (decoding, silence detection, encoding)
- A Google Cloud service account key with Text-to-Speech and Speech-to-Text
  enabled

On NixOS, `nix-shell` provides both tools.

## Setup

Drop a service account JSON key into `.env/`. The binary finds it on its own:

```
.env/your-project-key.json
```

Resolution order is `--credentials`, then `$GOOGLE_APPLICATION_CREDENTIALS`,
then the first service account key in `.env/`. Only `project_id` and
`client_email` are ever read from the file, and neither the key material nor the
file contents appear in any log or error message.

Then check everything is wired up:

```sh
go build -o arabic-tts ./cmd/arabic-tts
./arabic-tts doctor
```

`doctor` verifies ffmpeg, the credential file, and both APIs. Its API calls are
read-only: listing voices is free and recognition is sent one second of silence.
If an API is not enabled yet it prints the exact command to enable it.

## Usage

### Text to speech

```sh
arabic-tts tts "مرحبا بك"
arabic-tts tts --file script.txt -o out/episode.mp3 --voice ar-XA-Chirp3-HD-Kore
cat script.txt | arabic-tts tts -o out/episode.wav --rate 0.95
```

With no `-o`, output lands in `out/tts-<timestamp>.wav`. The extension picks the
format: `.wav`, `.mp3`, `.ogg`, `.m4a`.

The API accepts 5000 bytes per request, about 2500 Arabic characters. Longer
text is split at sentence boundaries, synthesised concurrently, and stitched
into one file. Short text going to a compressed format is requested in that
format directly and never touches ffmpeg.

| Flag | Meaning |
| --- | --- |
| `--voice` | Voice name; see `arabic-tts voices` |
| `--rate` | Speaking rate, 0.25 to 2.0 |
| `--pitch` | Pitch shift; rejected for Chirp 3 HD voices, which do not support it |
| `--volume` | Volume gain in dB |
| `--gap` | Silence inserted between stitched chunks (default 150ms) |
| `--markup` | Treat input as markup, enabling `[pause]`, `[pause long]` |
| `--ssml` | Treat input as SSML |

### Speech to text

```sh
arabic-tts stt audio/interview.m4a
arabic-tts stt audio/interview.m4a --format srt -o out/interview.srt
arabic-tts stt audio/lecture.wav --lang ar-EG --format json --concurrency 8
arabic-tts stt audio/long.mp3 --format srt --verbose
```

Any format ffmpeg can decode works. Audio under a minute is a single request;
longer audio is decoded to 16 kHz mono, split at silence, and recognised
concurrently.

| Flag | Meaning |
| --- | --- |
| `--format` | `txt`, `json`, `srt`, `vtt` |
| `--lang` | `ar-XA` (default), `ar-EG`, `ar-SA`, and other `ar-*` codes |
| `--segment-max` | Longest span per request; defaults to 55s, or 15s for subtitles |
| `--concurrency` | Parallel requests (default 6) |
| `--silence-threshold` | Silence detection threshold in dB (default -35) |
| `--silence-duration` | Shortest silence treated as a cut point (default 0.4s) |
| `--normalize` | Fold Arabic orthographic variants and drop diacritics |
| `--bom` | Prefix output with a UTF-8 byte order mark |

`--verbose` prints the segment plan: every span, its bounds, and whether the cut
had to be forced mid-speech because no silence was in reach.

Subtitle cues carry a right-to-left mark so players that do not auto-detect
direction still render Arabic correctly. Use `--no-rtl-mark` to omit it.

### Voices

```sh
arabic-tts voices
arabic-tts voices --filter Chirp3
arabic-tts voices --json
```

## Design notes

Three API limits shape this program:

1. **`BatchRecognize` reads only from Cloud Storage.** It cannot accept inline
   bytes, so with no bucket it is unusable, and long files are handled
   client-side instead.
2. **`StreamingRecognize` is capped at five minutes per stream** and expects
   roughly real-time pacing, which would make transcribing an hour of audio take
   an hour. Concurrent synchronous requests on silence-split chunks are far
   faster.
3. **Synthesis caps at 5000 bytes per request** and returns LINEAR16 wrapped in
   a WAV container. Responses are stripped of their headers before the PCM is
   concatenated, otherwise the output would carry headers buried mid-stream.

One consequence worth knowing: `chirp_3` does not support word-level timestamps,
so subtitle timing comes from segment boundaries. That is why `--format srt`
drops the default segment length to 15 seconds.

## Development

```sh
make build      # build ./arabic-tts
make test       # offline unit tests; no network, no billing
make lint       # go vet + gofmt check
make doctor     # build and run the preflight checks
make roundtrip  # synthesize a phrase, then transcribe it back
```

`go test ./...` never calls Google: the API surface is narrowed to two
interfaces in `gcp` and the tests supply fakes. The live tests are
behind a build tag and an environment variable:

```sh
make integration   # ARABIC_TTS_INTEGRATION=1 go test -tags integration ...
```

Both Chirp 3 tiers are premium. Check current pricing before long runs.

## Use as a Go library

Everything except the CLI is importable:

```sh
go get github.com/scuba-plaza/arabic-tts
```

```go
creds, err := config.ResolveCredentials("")
if err != nil {
	return err
}
client, err := gcp.NewTextToSpeechClient(ctx, creds)
if err != nil {
	return err
}
defer client.Close()
_, err = tts.Synthesize(ctx, client, "مَرْحَبًا بِكَ", tts.Options{
	Voice:    config.DefaultVoice,
	Language: config.DefaultLanguage,
	Output:   "out/hello.mp3",
})
```

Transcription works the same way with `gcp.NewSpeechClient` and
`stt.TranscribeFile`. [arabic-vocab](https://github.com/scuba-plaza/arabic-vocab)
uses both to voice and verify its Anki deck.

## Layout

```
cmd/arabic-tts      entry point
internal/cli        cobra commands, error explanation, exit codes
config              credential discovery and defaults
gcp                 client construction, narrow interfaces
tts                 text splitting, concurrent synthesis, voice listing
stt                 silence segmentation, concurrent recognition, formatters
audio               ffmpeg wrapper, pure-Go WAV reader and writer
arabic              diacritics, normalisation, RTL helpers
```
